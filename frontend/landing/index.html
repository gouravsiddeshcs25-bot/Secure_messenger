A chat app whose server can't read your chats.

Messages are encrypted in your browser and only opened on the other person's screen. The server passes along ciphertext it has no key for.

This is also a security lab: an insecure client runs on the same server, and an automated attack suite shows what goes wrong without each protection.

How a message travels

Your words only exist in readable form on the two screens at the ends.

  1. Keys stay with youYour browser makes your keys and locks them with your password. Only the public half is shared.
  2. Locked before sendingEach message gets its own key, a tamper-check tag and your signature.
  3. The server relays itIt stores ciphertext it has no key for, then deletes it once delivered.
  4. Checked, then openedThe receiver checks the signature, the tag and the message number before showing anything.

Two clients, one server

Both talk to the same backend, so any difference in the results comes from the client and the protections around it.

Secure messenger

  • Password login, stored only as an Argon2id hash
  • Keys made in your browser and locked with your password
  • Every message gets its own key and a tamper-check tag
  • Safety numbers, and a warning if a contact's key changes
  • Sensitive messages that disappear after a timer or one view
Open the messenger

Insecure client (attack target)

  • No password: anyone can act as anyone
  • Messages stored as plain text
  • No key checks, no replay or tamper detection

What it doesn't protect

  • The server still sees who talks to whom, when, and how long each message is.
  • The app's code is served by our server, so you have to trust the JavaScript it sends.
  • All message keys come from one shared secret per contact. Stealing it exposes that conversation. A Double Ratchet would fix this; it's future work.
  • Disappearing messages are enforced by the receiver's app. A modified app or a photo of the screen can still keep them.
  • The code has not had an independent security audit.
